# ember-pages

Публичные страницы приложения Ember для App Store: политика
конфиденциальности и поддержка, по паре ru/en с перекрёстными
ссылками. Статика без зависимостей и без сборки.

Каталог собран в ночь на 10 сентября 2026 и готов к публикации:
файлы на месте, ссылки проверены, дата вступления в силу проставлена
(9 сентября 2026), git-репозиторий инициализирован и закоммичен.
Не сделан ровно один шаг - тот, что требует учётной записи владельца.

## Что здесь лежит

    index.html        оглавление (иначе корень сайта отдавал бы 404)
    privacy.html      политика конфиденциальности, русская
    privacy-en.html   то же, английская
    support.html      поддержка и FAQ, русская
    support-en.html   то же, английская
    .nojekyll         отключает обработку Jekyll на GitHub Pages

## Почему имя репозитория менять нельзя

Адреса зашиты в приложение: `Ember/Features/Settings/AboutInfo.swift`,
константа `siteRoot = "https://1ntr0men.github.io/ember-pages"`. Из неё
собираются все четыре адреса, и выбираются они ПО ЯЗЫКУ интерфейса:
русскому - `privacy.html` / `support.html`, остальным девяти языкам -
пары с суффиксом `-en`. Репозиторий обязан называться ровно
`ember-pages`, быть публичным и лежать у пользователя `1ntr0men`.
Иначе надо править `siteRoot` в приложении - иначе ссылки из
"О приложении" уйдут в 404.

## Что осталось сделать владельцу

1) Создать ПУБЛИЧНЫЙ репозиторий `ember-pages` у пользователя
   `1ntr0men` (пустой, без README - он уже здесь).
2) Из этого каталога:

       git remote add origin git@github.com:1ntr0men/ember-pages.git
       git push -u origin main

3) Settings -> Pages -> Source: "Deploy from a branch" -> ветка `main`,
   папка `/ (root)` -> Save. Первая сборка занимает около минуты.
4) Проверить, что все четыре адреса отдают 200:

       for p in privacy privacy-en support support-en; do
         curl -o /dev/null -s -w "$p %{http_code}\n" \
           "https://1ntr0men.github.io/ember-pages/$p.html"
       done

5) Вписать те же адреса в App Store Connect: Privacy Policy URL
   (App Information) и Support URL (страница версии). Адреса в ASC и
   в приложении обязаны совпадать - это проверяет ревью.

## Что уже проверено здесь

1) Все внутренние ссылки разрешаются в существующие файлы (пять
   страниц, десять внутренних ссылок, ноль битых).
2) Плейсхолдеров не осталось: ни `example.com`, ни незаполненной даты.
   В `privacy.html` стоит "Действует с: 9 сентября 2026", в
   `privacy-en.html` - "Effective date: September 9, 2026".
3) Текст политики сверен с `Ember/PrivacyInfo.xcprivacy` и
   `EmberWidgets/PrivacyInfo.xcprivacy` по смыслу:
   `NSPrivacyTracking = false` и пустой `NSPrivacyTrackingDomains` -
   "нет аналитики, рекламы, трекеров, сторонних SDK";
   пустой `NSPrivacyCollectedDataTypes` - "не собираем, не передаём и
   не продаём никакие данные"; единственный required-reason API
   (UserDefaults, причины CA92.1 и 1C8F.1) - "хранятся только на вашем
   устройстве, в защищённом контейнере, общем у приложения и виджета".
   Утверждение "приложение вообще не обращается к сети" проверено
   грепом по обоим таргетам: ни URLSession, ни WKWebView, ни Network -
   ни одного вхождения.
4) Страницы отданы локальным сервером и отвечают 200 (см. отчёт
   docs/NIGHT-2026-09-10.md в репозитории приложения).

## Если текст политики меняется

Раздел "Изменения политики" обещает новую дату при каждом изменении -
значит, правя текст, обязательно двигать и дату в обеих языковых
версиях. Исходники этих же страниц лежат в репозитории приложения,
`app-store/site/`; при правках менять обе копии или переносить сюда.
